# Установка EAS Mail MCP

Поддерживаются macOS 14+ на Apple Silicon и Intel. Windows и Linux не входят в
релиз `0.2.0`.

## Установка через npm

```bash
npm install -g eas-mail-mcp@next
eas-mail-mcp --version
eas-mail-mcp native-path
```

Npm нужен для установки и запуска административных CLI-команд. При настройке
клиента записывается прямой путь к Rust-бинарнику, поэтому Node.js не остаётся в
фоновом MCP-процессе. Пакет не использует `install` или `postinstall` scripts.

## Настройка

Запустите единый мастер:

```bash
eas-mail-mcp setup
```

На первом запуске мастер предлагает импортировать готовый профиль или создать
его вручную. Затем он позволяет добавить несколько аккаунтов, по этапам
проверяет TLS, авторизацию, EAS 14.1, policy и FolderSync, предлагает отдельно
включить write-доступ и настраивает найденные MCP-клиенты.

Если команда получила готовый профиль, его можно импортировать заранее:

```bash
eas-mail-mcp profile import ./team-profile.toml
eas-mail-mcp setup
```

Профиль содержит адрес EAS-сервера, разрешённые почтовые домены, формат логина и
параметры TLS, но не пароль и не данные конкретной учётной записи. Для формата
`realm_username` достаточно ввести короткий логин: мастер сам создаст
`REALM\login`, независимо от shell. Пароль сохраняется в macOS Keychain только
после успешной полной проверки. Запись по умолчанию выключена.

Повторный `eas-mail-mcp setup` открывает меню добавления/исправления аккаунтов,
обновления пароля, профилей, write-доступа, клиентов и диагностики. Отдельные
интерактивные сценарии:

```bash
eas-mail-mcp account add
eas-mail-mcp profile add
```

Для скриптов сохраняются явные флаги и `--password-stdin`. Неполная команда без
TTY возвращает `INTERACTIVE_REQUIRED`, а `--json` оставляет вывод машинным.

Локальные файлы:

```text
~/Library/Application Support/EAS Mail MCP/profiles.toml
~/Library/Application Support/EAS Mail MCP/config.toml
```

## Подключение клиентов

```bash
eas-mail-mcp client configure codex
eas-mail-mcp client configure claude
eas-mail-mcp client configure opencode
```

Перед изменением пользовательских конфигов создаётся backup. Имя и версия
клиента сохраняются только для диагностики и не блокируют настройку. Команда
регистрирует MCP и удаляет устаревшие `approve`/`allow`-правила, созданные
предыдущими beta-сборками. Write tool выполняется сразу после вызова, если запись
включена для аккаунта.

Проверка после настройки:

```bash
eas-mail-mcp account list
eas-mail-mcp profile list
eas-mail-mcp doctor
```

Каждое активное MCP-подключение запускает отдельный Rust-процесс. Один клиент
может одновременно держать несколько задач, поэтому процессов может быть
больше, чем открытых приложений. Лимит idle RSS 20 MiB считается на процесс.
После изменения или удаления конфигурации перезапустите клиент: уже открытые
stdio-сеансы сами от редактирования файла не завершаются.

## Обновление и удаление

Обновление не удаляет локальные профили, аккаунты или Keychain:

```bash
npm install -g eas-mail-mcp@next
```

Удаление npm-пакета также оставляет пользовательские данные на месте:

```bash
npm uninstall -g eas-mail-mcp
```

Старый локальный `tar.gz`-установщик остаётся только резервным путём для пилота.

## Ограничения протокола

Поддерживается стандартный EAS 14.1 с Basic Auth поверх строгого TLS и путём
`/Microsoft-Server-ActiveSync`. OAuth, IMAP, Graph, нестандартный URL,
отключение TLS-проверок и подмена DeviceType не поддерживаются.
